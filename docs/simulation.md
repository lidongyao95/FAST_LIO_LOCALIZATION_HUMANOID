# 纯仿真

不需要机器人。虚拟的 G1 在 MuJoCo 的房间里走路，虚拟雷达产生点云，其余部分（建图、定位、导航）和真机用的是同一套程序。

开始前先完成[环境配置](setup.md)的第一部分。

整个过程两步：先建图，再导航。

## 第一步：建图

```bash
./g1_slam sim map
```

会打开两个窗口：

- **MuJoCo**：虚拟房间和机器人。
- **RViz**：雷达点云和正在生成的地图。

等机器人站稳，终端出现提示后，用键盘控制它在房间里走一圈：

| 按键 | 动作 |
| --- | --- |
| `w` / `s` | 前进 / 后退 |
| `a` / `d` | 向左 / 向右平移 |
| `q` / `e` | 向左 / 向右转 |
| 空格 | 停下 |
| 回车 | 保存地图并结束 |

按住键才会走，松手就停。键盘焦点要在终端窗口上。走到的地方才会进地图，所以把之后要导航的区域都走一遍，然后按回车。

地图保存在 `sim/generated/maps/room/`。

## 第二步：导航

```bash
./g1_slam sim nav
```

同样打开 MuJoCo 和 RViz。等终端显示“定位和导航已就绪”后：

1. 在 RViz 顶部工具栏点 **Nav2 Goal**。
2. 在地图的空白区域按住鼠标左键，拖动选择朝向，松开。

机器人会规划一条路线并走过去。RViz 里绿色的线是规划的路径，彩色区域是障碍物周围的禁行范围。

按 `Ctrl+C` 结束。

## 常用变化

**不用鼠标，直接给目标坐标：**

```bash
./g1_slam sim nav --goal 3.0 0.0
```

机器人走到 (3.0, 0.0) 后程序报告结果。

**走到一半放一个障碍物**，看它绕路：

```bash
./g1_slam sim nav --goal 3.0 0.0 --obstacle-after 2
```

**场景里加一块来回移动的挡板：**

```bash
./g1_slam sim nav --moving-obstacle
```

**保存多张地图**，给地图起名字：

```bash
./g1_slam sim map lab
./g1_slam sim nav lab
```

**没有显示器**（比如通过 SSH 连到服务器）时，程序自动不开窗口。这时建图不能用键盘实时控制，用 `--goal` 的方式导航，或直接运行自动测试：

```bash
./g1_slam test sim
```

它会自动建图、导航、放障碍、取消目标，并检查高速行走时的定位误差，约 12 分钟。

## 出问题时

每次运行的日志在 `sim/generated/logs/` 下最新的目录里，每个程序一个文件：

| 文件 | 内容 |
| --- | --- |
| `mujoco.log` | 仿真器 |
| `controller.log` | 行走控制器 |
| `mapping.log` / `localization.log` | 建图 / 定位 |
| `nav2.log` | 导航 |

终端提示“已有一轮仿真在运行”时，回到之前的终端按 `Ctrl+C`，或者运行：

```bash
python3 shared/processes.py --stop --domain 74
```
