# PC2 G1 自主行走开发与验收计划

**目标** 在吊架保护下验证从真机定位、Nav2 到运控的链路，再由现场负责人决定是否放行短程自主行走。

## 1. 吊架推行闭环 dry-run

- [x] 核对入口。现有 plan 模式只规划，full 模式面向仿真，控制器及恢复行为的速度重映射至 cmd_vel_nav。
- [x] 核对速度桥入口。candidate_velocity 已存在，硬件输出默认关闭。
- [ ] 核对 PC2 与记录端对时、地图版本、实测机体外参和 TF 发布权。
- [x] 增加独立的真机闭环 dry-run 入口，显式使用实机地图与墙钟，将控制器及允许的恢复行为速度接到 candidate_velocity。启动时验证没有机器人发送器订阅该链路。
- [ ] 吊架推行时记录目标、TF、配准、代价地图、候选速度、桥输出及状态。逐项验证可达、阻断、取消、到点和失败。取消、到点和失败后确认输出归零且旧目标不会恢复输出。
- [ ] 使用独立参考位姿核对动态定位误差，并对照实物位置验证障碍标记和清除。现场预先确定误差和延迟容差。

## 2. SDK 停机和接管

- [ ] 复跑确切候选的 SDK 与桥联测，涵盖命令超时、定位失效、点云和里程计过期、SDK 无响应，以及运控从 802 切到阻尼 1。记录停发时刻、最后非零请求、零速请求及确认结果。
- [ ] 现场负责人确认吊具、人员和停止手段后，在吊架保护下分别验收主动停车、物理断链和遥控阻尼接管。每项记录停稳时间、位移、运控状态和是否需要重新启用。物理断链观察最后一条指令到期后的机体行为。
- [ ] 任一项未确认停稳、意外恢复速度或存在状态冲突，暂停进入下一阶段。

## 3. 短程控制和放行

- [ ] 记录起步、直行、接近目标和停车时的速度与机体响应。根据实测整定控制器并复验到点。
- [ ] 直线通过后逐项验证转弯和实景障碍。
- [ ] 保存候选源码版本、地图和参数、运行日志及现场观察。由现场负责人决定是否放行。
