## 2. PC2 部署与构建

首次检查发现 `eth0` 的默认网关 `192.168.123.1` 不可达，较低的路由 metric 让 DNS 和 apt 失败。当时用以下命令恢复外网：

```bash
sudo ip route del default via 192.168.123.1 dev eth0
sudo nmcli connection modify unitree1 ipv4.never-default yes
```

随后 `apt-get update` 成功。复核时默认路由走 `wlan0`，`192.168.123.0/24` 仍经 `eth0` 直连。

选择保留 PC2 原生 Foxy，以 rsync 将仓库同步到 `/home/unitree/FAST_LIO_LOCALIZATION_HUMANOID`，排除了 Git 元数据、仿真子模块和开发机依赖产物。构建范围为 `livox_ros_driver2` 和 `fast_lio`：

```bash
cd ~/FAST_LIO_LOCALIZATION_HUMANOID
G1_BUILD_PACKAGES="livox_ros_driver2 fast_lio" ./scripts/build_g1_ros2.sh
```

- 构建、依赖准备与运行脚本增加了 Foxy/ARM64 适配，Open3D 仅在构建定位包时需要。FAST-LIO 去除未使用的 `pcl_ros`，补齐 `tf2_ros`、`tf2_msgs` 与 PCL filters，并调整了服务回调签名。
- 系统 Livox SDK 缺少当前驱动所需符号，改用仓库内 Livox-SDK2 1.3.1，在 PC2 本机编译后通过。Foxy overlay 能解析两个已安装的包，`ldd` 未报告缺失库。`open3d_loc` 和 `nav2_bringup` 在该环境中尚未解析到。
- PC2 驱动副本的 `MID360_config.json` 中五项接收 IP 均为 `192.168.123.164`，雷达地址为 `192.168.123.120`，JSON 外参为零。`msg_MID360_launch.py` 使用 `xfer_format=1`，将 `/livox/lidar` 重映射为 `/livox/custom_msg`。两处设置已在安装目录核对，重新同步源码前须保留 PC2 配置。

## 3. 静止采集、实时里程计与离线 PCD

PC2 原始录包在 `~/g1_real_data/bags/static_01`，参数在 `~/g1_real_data/config/mid360_real.yaml`。Mac 项目副本在 `tmp/g1_real_data/`，录包数据库、元数据和参数在复制时均通过 SHA-256 校验。

`ros2 bag info` 显示录包大小 44.9 MiB，时长 11.524 s。SQLite 只读复查确认两路消息头各自严格递增，坐标系均为 `livox_frame`。

| 话题 | 条数 | 包内平均频率 | 相邻消息头时间差（最小 / 中位 / 最大） |
|---|---:|---:|---|
| `/livox/custom_msg` | 115 | 9.98 Hz | 99.770 / 99.976 / 100.275 ms |
| `/livox/imu` | 2306 | 200.1 Hz | 3.914 / 4.793 / 6.038 ms |

每帧点数为 19,968–20,064，点云 `header.stamp` 与 `timebase` 一致。现场 `ros2 topic hz` 曾超时，频率采用录包计数与时长计算。

- **静止实时**：FAST-LIO 完成 IMU 和地图 KD 树初始化，发布 `/Odometry_loc`（`camera_init → body`）。低电前快速复验收到点云 4 条、IMU 19 条、里程计 3 条后收尾。
- **静止离线**：在本机隔离 ROS 域 193 用 Foxy 回放 `static_01`，设置 `use_sim_time:=false`，播放器直接运行 `ros2 bag play`。本机播放器无 `--clock`。调用 `/map_save` 返回成功，读回临时 binary PCD 文件头为 **10,661 点**，随后清理临时文件。B300 正式地图仍需行走录包与独立质量检查。

## 4. 时钟与换电后复验

| 检查 | 结果 |
|---|---|
| 换电前主机时钟 | chrony 运行中，`timedatectl` 显示未同步。两次检查分别比 NTP 慢约 680 s 和 659 s |

| 实时配准点云 | 实际收到 `/cloud_registered_1`（`PointCloud2`，`camera_init`）。一次测试的前五帧头部年龄约 1.01–1.37 s。另一次跳过探针启动前三秒，随后约 5 s 收到 46 帧，头部年龄最小 / 中位 / 最大为 24.34 / 37.06 / 40.62 ms |
| IMU 时间异常 | 同轮头部年龄中位数 0.71 ms，最大约 2.99 s。这里用 PC2 接收时钟减消息头时间，读数包含时钟、排队和探针接收因素 |
