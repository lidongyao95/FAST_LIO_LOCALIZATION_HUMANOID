# 2026-11-06 B 段独立重定位执行计划

本轮验收以 A 段冻结的三维 PCD 为地图，使用独立采集的 B 段数据、实测安装外参和独立参考位姿。先在 4322/Humble 回放，随后在 PC2/Foxy 做机载实时验收。两套结果分开报告。

依据 [PC2 调试汇总](2026-11-05_g1_pc2_debug_summary.md)、[A 段待办](2026-11-05_a_segment_open_items.md)和 [B300 实机指南 §7](../g1_real_robot_slam_pc2_b300_guide.md#7-地图定位)。本轮预检时 PC2 的 SSH 在 banner 交换阶段超时，本地仅找到 `static_01` 的录包元数据。现场验收待输入齐备后开始。

## 1. 冻结输入与现场条件

- [ ] 在 PC2 核对 `~/ldy/g1_real_data/{bags,maps,config}`，记录 A 段验收 PCD、B 段各包、两端源码版本、实际 overlay、定位配置及外参文件。对 PCD、配置和录包文件记录 SHA-256。用 `ros2 bag info` 核对 B 包时长、点云与 IMU 的类型和消息数，并确认 B 段采集与建图输入相互独立。
- [ ] 选门口标记点、走廊可辨识墙角和另一处不同朝向的标记点。用独立测量把三处机器人 `base_link` 的位置和航向登记到 PCD 的 `map` 坐标系，记录测量方法和不确定度。保存复测照片和门、家具、遮挡状态。定位输出自身不能作为参考。
- [ ] 现场负责人确认吊具、机体状态、路线、人员与停止手段。实时轮隔离速度桥与运控链，核对雷达和 IMU 数据及 chrony 状态，换电后复核。动态轮仅在现场放行后执行。
- [ ] 开跑前签记阈值。下表是本计划给出的首轮建议值，现场可在采样前修订，并记录理由和适用条件。

| 项目 | 首轮建议 |
| --- | --- |
| 初始误差 | XY ≤ 0.30 m，航向 ≤ 5°，相对独立参考位姿 |
| 初始化超时 | 首帧有效同步输入后 15 s，记录地图加载耗时及冷启动总耗时 |
| 静止漂移 | 初始化后连续观察 60 s，相对稳态首帧 XY ≤ 0.10 m、航向 ≤ 2° |
| 修正跳变 | 稳态相邻已接受的 `map → odom` 修正变化 XY ≤ 0.20 m、航向 ≤ 3° |
| 稳态配准 | 接受率 ≥ 90%，最大连续无接受时间 ≤ 3 s，包含到有效观测结束的间隔 |

## 2. 4322 离线回放

- [ ] 单独设置 ROS 域，清掉同域重复播放器、FAST-LIO 和定位进程。依 B300 指南 §6.3、§7.3 先启动 FAST-LIO 和实测静态 TF，确认 `base_link ← imu_link`、`motion_link ← base_link` 可查询。核对 `map → odom` 和机体链各边的发布者，确保同一子帧只有一个权威来源。
- [ ] 用 `ros2 run open3d_loc global_localization_node` 加载当轮实机 YAML 和 PCD，按指南重映射 `/map` 与 `/scan`，记录 `ros2 param dump /global_localization_node`。所有消费者设 `use_sim_time=true`，最后执行 `ros2 bag play "$BAG" --clock`。如果在 Foxy 补做离线对照且播放器缺少该选项，先启动仓库的 `scripts/replay_clock.py`，再启动播放器。每轮只允许一个时钟源。
- [ ] 每点做 3 次独立进程启动，共 9 个正常用例。每次重启定位和 FAST-LIO、从头播放该点对应独立 B 包。加一个偏初值用例，建议在同一点正常初值上偏移 0.5 m 和 15°，另记实际偏移。偏初值用例单列，检查是否回到正确参考点，误配单独判失败。
- [ ] 用扫描叠图复核门框、墙角和走廊，记录参考点、初值和最终位置。若使用 4322 上的 RViz，检查实际 OpenGL 渲染器及 RViz PID 在 `nvidia-smi` 的记录，使用 GPU 渲染。

## 3. PC2 机载实时

- [ ] 停止回放和模拟时钟。确认 PC2 当前 overlay 含实机驱动、FAST-LIO 和定位包。切换至实时雷达和 IMU，全部使用 `use_sim_time=false`。沿用同一 PCD、实测 TF、正常初值策略与判据。
- [ ] 在相同三处分别重新摆位和独立启动 3 次。每轮静止记录 60 s 稳态。动态轮经过独立测量的检查点后回到起点，核对检查点误差、回起点误差与修正跳变。遇到错误地点的配准、输出超时或 TF 冲突，结束该轮并保存现场证据。
- [ ] 同步记录 CPU、RSS、可用内存、温度、输入频率、消息数及时间戳延迟。用实测输入与输出时序判断积压，给出丢帧统计的观测口径。若确需远端补构建，后台日志加 `--event-handlers console_direct+`，每 20–30 秒检查进程、日志增量与终态，失败定位根因后重试受影响包并同步进展。

## 4. 统计与交付

- [ ] 每轮保存定位 stdout、实际参数、参考位姿、传感器和位姿时间戳、`/tf`、`/tf_static` 和必要的叠图证据。用 `map → base_link` 计算 XY 误差和归一化航向差，单独用 `map → odom` 检查全局修正跳变。日志和数据统一记录时间域。
- [ ] 稳态以 `open3d_loc/src/global_localization.cpp` 的 `reg_result.fitness: ..., eva fitness: ...` 日志计数。每行算一次评估，取第二个值与运行时 `threshold_fitness` 做严格大于比较，计算接受次数、评估次数、接受率及最后接受事件的日志时间。阈值附近若因日志精度无法判定，标记该事件不可判定并复核。连续无接受时间按同一事件时间轴统计。`/localization_3d_confidence` 是缓存 fitness，`/localization_3d_delay_ms` 用于里程计年龄。
- [ ] 分平台归档逐轮结果，字段包含用例、启动序号、PCD/录包、初值、参考位姿、初始化用时、XY/航向误差、漂移、最大修正跳变、接受数/评估数、最后接受时间、最大接受间隔、资源和判定。正常用例按 9/9 通过验收，偏初值和动态轮各列结果。缺实测参考、正式地图、独立样本或有效计数时记录缺项并保留待验状态。
