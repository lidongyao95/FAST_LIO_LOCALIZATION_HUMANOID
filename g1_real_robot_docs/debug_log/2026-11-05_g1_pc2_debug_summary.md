## 2. 待办

1. **现场放行与环境检查。** 现场负责人签记吊点、吊具载荷、允许机体状态、停止手段、人员与路线。保持速度桥与运控链隔离。放行不足时继续用已有录包。采集前及换电后记录 chrony 状态，核对雷达、话题和 ROS 环境。
2. **收尾 A 段。** 用实测安装方向、安装外参和受控动态样本核对位姿符号、尺度、逐点时间及 LiDAR/IMU 对齐。核对 A 盒与当前吊具位置。按覆盖、重影、尺度和回起点接缝验收三维图，再核对二维图的起点、门口、墙角和未知区。保留原始录包，给复采、候选图和验收结果分别编号。
3. **执行 B 段。** 使用与 A 段独立的数据，预先确定位置、航向、漂移、跳变和超时容差。选 3 个实测位置与朝向，每处独立启动 3 次，另做偏初值或相似结构用例。记录初始化误差、持续定位、稳态配准接受率及最后接受时间，并分开统计 PC2 机载实时与 x86 离线表现。
4. **执行 C 段现场仅规划。** A 段二维图与 B 段定位通过后，显式传入 `mode:=plan map_yaml:=<已验收地图> use_sim_time:=false`。检查 TF 发布权、地图和规划节点状态、`costmap_raw` 及障碍源。用 `ComputePathToPose` 验证可通行目标、阻断目标及真实障碍标记与清除。
5. **整理部署和证据。** 刷新 4322 常用部署的 `install/`，核对实际 overlay。远端构建使用 `console_direct+` 和后台日志，每 20–30 秒检查进程、日志增长与终态。先归档引用的日志、参数和指标，再清理临时验证目录。按实际证据回写真机验证状态。

## 3. 已解决的坑

| 问题 | 根因与处理 |
| --- | --- |
| PC2 外网不可达 | 默认路由优先走网关不可达的 `eth0`。临时移除该默认路由后，外网走 WLAN，机器人和雷达网段仍经 `eth0` 直连。 |
| Livox 构建或启动无数据 | 系统 SDK 缺新版 MID-360 类型，改用仓库固定版本 SDK，重新生成 ROS 2 包清单和 launch，核对 PC2 接收地址 `192.168.123.164`、雷达地址 `192.168.123.120` 及安装副本。驱动 launch 用 `launch_ROS2/` 下的实际路径。 |
| Open3D 在 Foxy 构建失败 | 兼容 tf2 头文件 `.h` / `.hpp`，移除未用头文件。ARM Open3D 保持完整解包结构，`Open3D_DIR` 指向真实 CMake 目录，缺失的 `liblapacke.so` 由 `liblapacke-dev` 补齐。 |
| 定位空裁剪或启动失败 | DDS 尚未发现安装 TF 时旧代码继续用未赋值矩阵。定位线程启动前等待 `base_link ← imu_link` 与 `motion_link ← base_link`，两项共用 5 s 单调时钟预算，缺失时明确报错退出。另修复 FastRTPS 队列深度、节点名与 YAML 不匹配、六元素初值校验及滤波参数键。 |
| 建图输入与输出边界 | 实机 `/livox/lidar` 是 `CustomMsg`，FAST-LIO 保留 `lidar_type: 1` 并按需重映射原配置的 `/livox/custom_msg`。帧尾取最晚点，避免点时间局部逆序造成误判。`/map_save` 改为原子写入并报告失败，近零 IMU 加速度加了除零防护。 |
| 吊架污染与重复回放 | A 盒在倒装补偿后、去畸变和配准前生效，默认关闭。B 盒额外删去约 36 万个环境回波，起点改善很小，当前仅采用 A 盒做候选图。一次建图发散由同域重复播放器引起，清理后重跑通过。 |
| Foxy 回放时钟停在零 | 实装播放器没有 `--clock`。新增 `replay_clock.py`，从 IMU 戳加默认 100 ms 发布单调 `/clock`。单次静止回放观测领先中位 94.8 ms，代价地图恢复更新，无时钟对照停在 `Checking transform`。 |
| 障碍层收不到实机数据 | 仿真同名话题用 `PointCloud2`，与实机 `CustomMsg` 类型不同。Nav2 全局、局部障碍源及生成器改用 FAST-LIO 的去畸变机体云 `/cloud_registered_body_1`，保留驱动原始逐点时间。 |
| Foxy 距离参数与部署漂移 | Foxy 读取 `obstacle_range`、`raytrace_range`，Humble 读取 min/max 键。候选副本一度通过但部署仍取 Foxy 默认 2.5/3 m，经 `rsync -ain` 定位 YAML 和生成器差异并同步，两端复测读回 8/9 m，4.025 m 恢复标记。 |
| 地图参数覆盖与规划启动 | 清理开发机绝对路径，父子定位 launch 显式传递 `path_map`。导航入口将地图与时钟写进同一份临时参数文件，双端读回验证。非法参数提前退出，生命周期助手失败时关停。Foxy 内置 global costmap 的生命周期查询可能显示 `unconfigured`，验收看 `costmap_raw`。 |
| 规划起点落在墙里 | 合成图首轮起点位于隔断墙格，三个目标均中止。把起点移到空闲格后，绕行与短距通过，封闭目标按预期返回空路径。 |

## 4. 还要确认

- **吊具与正式底图。** A 盒在换吊具、改变安装位或 G1 相对吊架转向后需重测。核对 `d_p=1` 额外删除的栅格中，距轨迹超过 1.3 m 的 271 格是否对应墙、门框或家具。
- **时钟与 TF。** 复查 PC2 重启后路由及换电后对时，历史曾见约 680 s 主机偏差。单次静止回放的 94.8 ms 是时钟领先量，动态端到端延迟、点云与 TF 的时间覆盖及仿真中早于 TF 缓存的告警仍需用同步样本追踪。
- **定位精度与资源。** 核对实测外参下的独立起点定位误差、误配、漂移和修正接受事件。记录 PC2 冷启动、稳态与受控动态下的 CPU、RSS、可用内存、温度、输入积压和丢帧。
- **实景障碍与清除。** 核对 global 的 `map` 与 local 的 `odom` 地板高度、滤波阈值、低矮障碍和近距遮挡。验证 IMU 原点作为射线起点的影响，并与实测 LiDAR 原点比对。Foxy 近距 0.4 m 行为、局部滚动窗口及接近 9 m 的清除范围仍待验，现有受控清除探针测到 8.125 m。
- **边界回归。** 补测零值 IMU 后恢复、非有限输入、未知第四字段点云和驱动多次退出。确认 NoMachine 无显示器会话能正常显示 RViz。步态、行走振动下定位、实际避障、到点精度、停止、接管和断链行为留待真实行走轮次。
