## 3. 已核实可保留的内容

- 第 5 章核心话题和类型与 `laserMapping.cpp:946–959`、`global_localization.cpp:263–285` 一致；CustomMsg 不能靠重命名变成 PointCloud2。
- 第 6 章 `/map_save` 要在 FAST-LIO 仍运行时调用，且 `pcd_save_en` 必须开启。服务当前没有把底层写入结果转成失败，必须独立读回；原文对此描述正确（`laserMapping.cpp:1143–1159`）。
- `export_g1_map.py` 支持未压缩 binary PCD，生成 PLY、PGM、YAML 和元数据；默认原点附近补空闲半径为 1.5 m，原文显式关掉该项合理。
- 定位节点使用 Open3D `ReadPointCloud`，原文传入 PCD 不是仅因旧 launch 使用 PLY 就必然错误；最终仍需在固定 Open3D 版本上实际读回验证。
- 初始欧拉角以度解释、FAST-LIO 的 `camera_init → body`、定位 `/map` 与 Nav2 栅格 `/map` 类型冲突等判断成立。
- 本地 SDK 确有 `SetVelocity(vx, vy, omega, duration=1.f)` 与 `StopMove()`；持续移动封装可使用很长 duration，桥设计应显式选有限有效期。源码不能证明固件实际过期行为。
- 保留独立 A/B 数据、回放与实时分开验收、先定位再导航，以及不将仿真低层控制入口直接用于真机的范围限制。
